# 📊 Complexity Reference

| Data Structure / Algorithm | Typical Time |     Space |
| -------------------------- | -----------: | --------: |
| Array Access               |         O(1) |      O(1) |
| Array Search               |         O(n) |      O(1) |
| Linked List Search         |         O(n) |      O(1) |
| Linked List Insert at Head |         O(1) |      O(1) |
| Stack Push                 |         O(1) |      O(1) |
| Stack Pop                  |         O(1) |      O(1) |
| Queue Enqueue              |         O(1) |      O(1) |
| Queue Dequeue              |         O(1) |      O(1) |
| Hash Table Lookup          |        O(1)* |     O(1)* |
| Binary Search              |     O(log n) |      O(1) |
| Merge Sort                 |   O(n log n) |      O(n) |
| Quick Sort                 |  O(n log n)* | O(log n)* |
| Binary Tree Search         |         O(n) |      O(h) |
| BST Search                 |    O(log n)* |      O(h) |
| BFS                        |     O(V + E) |      O(V) |
| DFS                        |     O(V + E) |      O(V) |

* Average or typical case; worst-case complexity can differ.

# 🧠 Problem-Solving Process

For every problem, I will follow this process:

### 1. Understand

* What is the problem asking?
* What are the inputs?
* What is the expected output?
* What constraints exist?

### 2. Think

Before writing code:

* What data structure can help?
* What algorithm can help?
* Can I solve it without brute force?
* What patterns do I recognize?

### 3. Implement

Write the solution myself.

No copying solutions.

### 4. Analyze

Determine:

```text
Time Complexity: O(?)
Space Complexity: O(?)
```

### 5. Test

Test:

* Normal cases
* Edge cases
* Empty input
* Single element
* Large input
* Duplicate values
* Negative values where applicable

### 6. Review

After solving:

* Can I explain the solution?
* Why does it work?
* Can I implement it again without looking?
* Is there a better approach?
